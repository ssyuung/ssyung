# 계약 변경 요청: 이동 묶음 0명은 위반이 아니라 지원 공백

- 요청 모듈: M1
- 날짜: 2026-10-22
- 바꿀 것: `docs/architecture.md` §8.5 문구, `packages/schema/src/scheduler.ts`의 `ViolationCode` 설명
- 하위 호환: 예(타입은 그대로, 의미만 명확히)

## 이유
§8.5에는 "이동 묶음에 2명 이상 또는 0명"이 하드 제약 위반이라고 되어 있다. 그런데 0명은 사람이 모자라서 생기는 결과이고, 이미 부족분(`Shortfall`, priority `MOVE`)으로 나간다.

0명을 위반으로 세면 공백이 있는 선택지가 모두 위반이 된다. 그러면 "반환한 모든 선택지는 validate() 위반 0건"이라는 M1 완료 조건과 부딪힌다.
- 예: `propose.staff-away.output.json`의 선택지 C는 `mv:2026-09-18:b2:1-3`이 0명(지원 공백)이고, 목데이터의 기대 결과다.
- 목데이터 생성기(`scripts/mock/build-mocks.ts`의 validate)도 이미 2명 이상만 위반으로 본다.

## 제안
- §8.5: "하드 제약 위반(겹침, 근무 밖, 고정 해제, 이동 묶음에 2명 이상)과 부족분(이동 묶음 0명 포함)을 돌려준다"
- `ViolationCode`의 `MOVE_GROUP_HEADCOUNT`에 `.describe("이동 묶음 담당이 2명 이상. 0명은 부족분")`을 붙인다.

## 영향받는 모듈
- M1: 이미 이렇게 구현했다.
- M2: CP-SAT도 0명을 부족분 변수로 둔다(§8.2-1과 같음).
- M8(W4): 0명 묶음은 빨간 빗금(공백)으로 그린다.

## 그동안의 우회
요청대로 동작한다. `MOVE_GROUP_HEADCOUNT`는 2명 이상일 때만 낸다.
