# M6 질문

## 설계 변경 (사람과 합의함, 2026-10-22)
지시서는 "input_schema는 ChangeOps.json, InterpretContext를 프롬프트에 넣는다"인데, 사람과 합의해 이렇게 바꿨다. 지시서 문구는 사람이 고친다.
- 모델은 **구조화된 출력**(`output_config.format`)으로 문장 속 표현만 뽑는다(`src/extract.ts`, M6 내부 형식).
- 날짜·교시·과목·코드 계산은 **해석 함수**(`src/resolve.ts`)가 `InterpretContext`로 한다. 프롬프트에는 원문만 들어가고 컨텍스트는 보내지 않는다.
- 결과 계약(`ChangeOps`, `InterpretResult`)은 그대로다. 계약 변경 요청은 필요 없어져 철회했다.
- 같은 반에 같은 별칭은 없다고 본다. 번호(출석번호)는 다루지 않는다. 다른 반에 같은 별칭이 있으면 반으로 구분하고, 안 되면 후보를 알려 준다.
- 별칭 목록은 모델에 보내지 않는다.
- 22건의 정답 추출값은 `test/extractions.ts`에 직접 둔다(M6 내부 형식이라 fixtures가 아님).

## 남은 질문
1. **새 의존성 `@anthropic-ai/sdk` (^1.1.0)**: 지시서가 공식 SDK를 지정해서 추가했다. 테스트는 타입만 쓰고 SDK를 실행하지 않는다.
2. ~~**1차 모델**~~ → **답함(2026-10-22): Haiku 5.5로 바꾼다.** eval 22건에서 둘 다 정확도 22/22, Haiku 5.5는 재시도 0·1건당 약 0.14원(Haiku 4.5는 약 6.53원). 지시서의 "Haiku 4.5" 문구는 사람이 고친다.
3. **unsupported면 재시도하나?** cost-strategy.md §2.4 그림은 그렇지만 지시서는 낮은 확신·검증 실패만 적었다. 지시서대로 했다.
4. **재시도 기준**: 모델이 값을 잘못 뽑았을 수 있는 실패(모르는 학생·장소·과목, 없는 교시, JSON 오류, confidence low)만 2차로 보낸다. 수업일 아님, 다른 반 같은 별칭처럼 코드가 확정한 실패는 보내지 않는다.
5. **API 오류**(네트워크·5xx·429)는 SDK 재시도(기본 2회) 뒤 그대로 throw한다. M7이 오류로 보여 주는 것이 맞는지?
6. **업무(duty) 고정**: `InterpretContext`에 업무 목록이 없어 pin의 target duty는 아직 못 만든다(학생 고정만).
7. **컨텍스트 만들기**: architecture.md 폴더 설명은 interpreter에 "컨텍스트 사전 계산"을 넣었지만, 지시서는 범위 밖(M7·core)이다. 지시서대로 받기만 한다.
8. **eval 정확도 정의**: ops(순서 무시, when 하나와 원소 하나짜리 배열은 같음)·scope·unsupported 여부가 같으면 정답. unsupported 문구와 confidence는 따로 센다.
