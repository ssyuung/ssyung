        4. 답변을 반영해 바뀌는 데이터 구조

        가장 큰 변화는 D1입니다. 학생 배치를 교사가 정하므로 시간표 엔진은 지원인력 배정만 계산합니다. 자주 바뀌는 데이터(배치, 지원 필요 칸, 부재)는 버전마다 복사해 두어 롤백하면 함께 돌아옵니다.

        결정바뀌는 점테이블
        D1 배치는 교사가 정함, 수정 가능배치는 계산 결과가 아니라 입력값입니다. 버전 데이터로 두고 변경 요청(set_placement)으로 고칩니다.student_placement (버전별)
        삭제 student_plan (주당 시수)
        D2 지원인력 유형 동일유형 컬럼 없음staff 그대로
        D3 수업 외 일정 · D10 쉬는 시간도 배정교시 대신 시간 칸을 다룹니다. 쉬는 시간, 점심, 등하교에도 지원 필요 칸과 업무를 둘 수 있습니다.period_slot → time_block
        신규 duty, support_requirement (버전별)
        staff_assignment: 학생 또는 업무
        D4 특수학급·교사 여러 개학생은 특수학급 하나에 속하고, 교사는 여러 학급을 맡을 수 있습니다.신규 special_class, special_class_teacher
        D5 메모 · D8 맡은 학생만지원 방법(교사 관리)과 메모를 분리합니다. 지원인력은 활성 버전에서 현재 맡은 학생의 것만 봅니다.신규 memo, memo_read
        RLS: 현재 담당 학생 함수
        D6 계속 수정학기 개념 없이 버전이 이어집니다.schedule_version 그대로
        D7 승인은 교사 누구나학급별 승인 권한 없음approval.approved_by
        D9 학생 동행 업무업무에 학생을 연결합니다. 직전에 그 학생을 지원한 사람이 맡도록 우선합니다.신규 duty_student

        5. 확정된 답변

        1. 승인 권한. 학교의 교사 누구나 승인합니다.
        2. 메모 범위. 지원인력은 현재 맡은 학생의 메모만 봅니다. 담당이 끝나면 접근이 끊깁니다.
        3. 학생 동행 업무. 있습니다. 업무에 학생을 연결합니다.
        4. 쉬는 시간. 배정 대상입니다. 같은 학생을 이어서 지원하면 이동 제약을 적용하지 않습니다.
