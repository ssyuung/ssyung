# 배치 엔진 연쇄 시나리오

> 배치 엔진(`packages/scheduler`, architecture.md §8.0)을 고칠 때마다 돌리는 시나리오 10개. 기계용 파일은 [`fixtures/scenarios/cascade-scenarios.json`](../fixtures/scenarios/cascade-scenarios.json).
> 기본 데이터: `dataset/` (서울개포초 9월 시간표, 학생 S01–S07 = 학생1~7, 지원인력 A01–A03 = 지원인력1~3, 모두 풀타임). 화면 표시는 별칭, 데이터는 코드.

## 정책 (선택지, D23)

| 키 | 이름 | 규칙 |
|---|---|---|
| A | 변경 최소 | 이전 배정 유지, 체크된 시작 구간은 비우지 않음 |
| B | 처음부터 다시 | 이전 배정에 묶이지 않고 다시 배정 |
| C | 늦게 도착 없음 | 두 번째 이동을 쓰지 않음, 모자라면 지원 공백 |

## 판정 기준

- 모든 선택지가 독립 제약 검사기를 통과한다(한 사람 한 시점 한 곳, 근무 시간, 묶음은 1명, 두 번째 이동은 다음 교시 첫 10분까지).
- 시나리오마다 `expect`의 바뀌는 칸 종류와 연쇄 이유 코드가 나온다.
- 정책별 지원 공백(`gaps`)과 늦게 도착 학생 수(`late`)가 기준선보다 나빠지지 않는다. 좋아지면 기준선을 갱신한다(계약 변경 절차).

## 임시 규칙 엔진 기준선

바뀌는 칸 / 지원 공백 / 늦게 도착 학생 수. 원본은 `fixtures/scenarios/cascade-scenarios.json`이고 `pnpm mock:build`가 시안 엔진으로 다시 계산한다(입력 파일이 있는 시나리오). \* 표시는 D25(특수학급 시간표) 이전 데이터 값으로, M3 merge 뒤 입력 파일과 함께 다시 계산한다.

| # | A 변경 최소 | B 처음부터 다시 | C 늦게 도착 없음 |

| S1 | 7 / 0 / 0 | 8 / 0 / 0 | 7 / 0 / 0 |
| S2 | 4 / 0 / 1 | 9 / 0 / 1 | 4 / 1 / 0 |
| S3 | 7 / 1 / 1 | 7 / 1 / 1 | 7 / 2 / 0 |

| S7 | 6 / 4 / 1 | 0 / 4 / 4 | 7 / 5 / 0 |
| S8\* | 4 / 2 / 2 | 8 / 2 / 3 | 6 / 4 / 0 |
| S9\* | 4 / 0 / 0 | 8 / 0 / 0 | 4 / 0 / 0 |
| S10\* | 5 / 0 / 0 | 11 / 0 / 0 | 5 / 0 / 0 |

- S7은 변경 없이 그날 배정 자체를 본다. 이 날은 쉬는 시간마다 이동 묶음이 4개라 지원인력 3명으로는 두 번째 이동이 필요하다.
- S8은 S7과 같은 날에 학생 설정만 바꾼다. 정책 A의 지원 공백이 S7보다 줄어야 한다.
- S7이 D25 뒤 나빠졌다(A 공백 3 → 4). 특수학급 장소가 시간표로 정해지면서 9/15의 이동이 더 몰렸기 때문이다(엔진은 같음).
- S6·S8·S10은 변경 요청(ChangeOps)이 아니라 기초정보 수정·시간표 다시 가져오기로 시작한다. 같은 엔진을 같은 방식으로 부른다.
